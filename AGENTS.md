# AGENTS.md

## Commands

- `bun install`
- `bun run tui` - run the app (accepts an optional collection path argument)
- `bun run dev` - watch mode
- `bun run build` - compile a standalone `termurl` binary via `bun build --compile`. Requires Bun >= 1.3.13 on macOS: 1.3.12 shipped a codesign regression and its unsigned binaries are SIGKILLed on launch.
- Release Please runs from `.github/workflows/release.yml` and uses Conventional Commits to create versioned release PRs, tags, and GitHub Releases. `.github/workflows/binaries.yml` publishes macOS ARM64/x64 and Linux ARM64/x64 assets plus `SHA256SUMS`, then updates the Homebrew tap and publishes signed pacman packages to the multi-package `msegoviadev` repository at `msegoviadev/pacman-repo` (`gh-pages` branch, served at `https://msegovia.dev/pacman-repo/$arch`, signed with the key in the `PACMAN_REPO_GPG_KEY` secret); see `RELEASING.md`. `pacman/termurl/PKGBUILD` is the reference pacman recipe; its `options=('!strip' '!debug')` is load-bearing because stripping removes the bundle embedded by `bun build --compile`.
- `bun run typecheck` - the only verification gate; CI runs exactly this and nothing else. There are no tests, lint, or formatter.
- `termurl doctor`, `termurl list`, `termurl show`, `termurl env`, and `termurl run` provide the headless CLI for agents and scripts. `termurl run` accepts explicit request names or `.hurl` files in argument order; it does not execute directories.
- Run the script, not bare `tsc`: it passes explicit flags (`--module NodeNext --moduleResolution NodeNext --resolveJsonModule --skipLibCheck`) that override `tsconfig.json` (which says `module: Preserve`, `moduleResolution: bundler`), and only checks `index.ts`.

## External dependency

- Requires the `hurl` binary (v8+) on `PATH`, spawned via `Bun.spawn`. It is not an npm dep. Typecheck passes without it, but running requests fails.

## Architecture

- Entire app is one file, `index.ts` (~3200 lines), the package `module` entry. Uses `@opentui/core` renderables directly; no React despite `jsx` in tsconfig.
- Collection resolution: `~/.config/termurl/config.toml` (respects `XDG_CONFIG_HOME`) is mandatory; a missing config exits with an error suggesting `termurl init`. A CLI arg overrides the collection for a single run, but config must still exist. There is no CWD fallback. Requests live under `<collection>/requests` and flows under `<collection>/flows`; environment dotfiles and `.termurl/` stay at the collection root. Never use `import.meta.url` for paths; it breaks under `bun build --compile`.
- `termurl init` is an interactive installer: prompts for the collection path (default `~/collection`), writes the config, and scaffolds a starter collection (`requests/httpbin/get.hurl`, `flows/`, `.env.dev`, `.env.example`). It refuses to overwrite an existing config.
- `termurl init --yes [path]` is the non-interactive installer for agents. `termurl doctor` can run without a valid config and reports setup failures as structured checks (including a `requests` directory check) with `--json`.
- Headless output keeps stdout pipe-safe: `run` writes response bodies or JSON to stdout, while reports and diagnostics go to stderr. Exit codes are 0 for success, 1 for usage/configuration errors, 2 for runtime errors, and 3 for assertion failures.
- `skills/termurl/SKILL.md` documents the minimum agent workflow: doctor, discover, inspect, choose an environment, and run explicitly named requests.
- Flow execution: queued requests are concatenated into one temp `.hurl` file, with `[Options] output:` injected per request to capture bodies. Captures (e.g. `token`) feed later requests in queue order. Queue keys are `name` or `name@variant`; `resolveKey` turns them back into run targets.
- Both `config.toml` and environment dotfiles are parsed by the same hand-rolled `KEY=value` parser (`parseVariables`). Keep both to simple `key = "value"` or `KEY=value` lines; no TOML sections, no multiline values.
- Colors come from a single `Palette` object `C` resolved by `resolvePalette(CONFIG)` before any renderable is constructed; never hardcode hex literals elsewhere. Config `theme = "system"` (Linux only) maps the active Omarchy theme's `colors.toml` (`$XDG_STATE_HOME/omarchy/current/theme/colors.toml`, parsed by `parseVariables`) onto the palette; any failure or other `theme` value falls back to `DEFAULT_PALETTE` (Tokyo Night). With `theme = "system"`, `watchOmarchyTheme` watches both the theme directory (in-place `colors.toml` rewrites) and its parent `current/` directory, because `omarchy theme set` swaps the whole `theme/` directory via `rm`+`mv` rename, which kills the directory watcher's inode silently; the theme-dir watch is therefore re-established after every debounced change before `applyPalette` runs. `applyPalette` mutates `C` in place (so render paths reading `C.*` update for free), re-applies construction-time colors on every static renderable, rebuilds the `SyntaxStyle` objects (`buildVariableSyntax`/`buildResponseFailureSyntax`, both `let`, never cached beyond a frame), and re-runs the render functions. `TextRenderable` (tabBar, statusBar) exposes `fg`/`bg` setters, not `backgroundColor`. `TextareaRenderable` keeps separate unfocused and focused color pairs and swaps them in `focus()`/`blur()` via `updateColors()`; the `backgroundColor`/`textColor` setters only touch the unfocused pair, so `applyPalette` must go through `applyTextareaColors` (sets `backgroundColor`/`textColor`/`focusedBackgroundColor`/`focusedTextColor`) for every textarea, otherwise a focused pane repaints with the stale startup palette after a theme switch.

## Conventions

- One request per `.hurl` file under `<collection>/requests` (sibling of `<collection>/flows`); the path under `requests/` becomes the request name; first `#` comment becomes the description. `loadRequests`/`loadRequestDirs` walk `join(collection, "requests")`, and request create/rename/delete join `requestsBase()`; flow discovery stays under `<collection>/flows`.
- Variants: a file may hold multiple hurl entries. Entry 1 is the default; later entries preceded by `# variant: <name>` are pickable variants (unmarked ones auto-name as `entry-N`). `parseEntries` splits a file into entries with string spans; `entrySource(req, variant?)` returns one entry's text. Running, `renderCurl`, copy-as-hurl/curl, and `captureNames` all operate on the selected entry only. CLI addresses variants as `name@variant` or `--variant`.
- Flows are named ordered groups saved as `.flow` files under `<collection>/flows/`. One `request[@variant]` per line, `#` comments ignored, first `#` comment becomes the description. `flowName` drops the `.flow` suffix and the leading `flows/`; `parseFlow`/`readFlowFile`/`loadFlows` mirror the `.hurl` cache (`flowCache`, cleared by the collection watcher). `resolveFlow` maps steps through `resolveTarget` and errors before running anything. CLI `run` resolves each input to a request first, then a flow, flattening the flow's steps in place into the same `runHurl` call (so captures span the whole run); `flows list`/`flows show` expose discovery. The TUI Flows tab (key `2`) mirrors the Environments window: `flowWindow`/`flowList`/`flowDetail` plus an inline `flowNameInput` for `a`/`r`, and a right column with the step editor above `flowResponseBox`/`flowRespView`; the list is a tree (`flowRows`/`flowCollapsed`, from `loadFlowDirs` + `flows`) so folders are selectable. `enter`/`l` runs the selected flow via `runNamedFlow` -> `runFlowTargets` (shared with the queued `runFlow`) or toggles a folder, `e`/`i` opens the editor (`vimNormal` editKind `"flow"`), `ctrl-a`/`:add` appends the selected requests-tab request, `J`/`K` (`moveFlowLine`) reorders, `a`/`r`/`d` create/rename/delete, and `saveFlowFile`/`loadFlowFile` treat the `.flow` file as the source of truth. `runFlowTargets` takes a `surface` (`"requests"`/`"flows"`), renders to `respView` or `flowRespView`, and `focusResponse` moves focus to the matching response pane after every run (`runRequest` included); `escape` returns to the list. The requests-tab flow picker (`ctrl-g` / `:flows`) and `:saveflow[!] <name>` remain quick shortcuts; `:newflow <name>` creates a flow. Tab order is `1` Requests, `2` Flows, `3` History, `4` Environments.
- Create/rename/delete are unified in both list panes: `a` opens an inline name input rendered above the list (Requests: under the `/` filter; Flows: as the first row of the list box), `r` renames the selected row, `d` arms `pendingDelete` and asks `(y/N)` before deleting (`parseNameInput` reads a trailing `/` as a folder, otherwise a file; the extension is appended). The Requests tree includes real directories from `loadRequestDirs` (empty folders included). Renaming a request rewrites every matching `.flow` step line via `transformFlowText` (comments/blank lines/`@variant` preserved); renaming a folder rewrites the `old/` prefix for all requests beneath it. Deleting a request/folder removes those step lines (cascade). `remapRequestReferences` keeps `flowQueue`/`activeVariant`/`lastResult`/`lastBodies`/`editorEntry` in sync, and rename/delete block when a dirty buffer would be clobbered. Context-aware `:rename`/`:mv` route to the flow or request selected row. Both list panes render folders and flow files in `C.fg`, with selection shown only by the `C.selected` background; request rows are colored by HTTP method via `methodColor` (GET green, POST blue, PUT yellow, PATCH magenta, DELETE red, HEAD orange, OPTIONS fg, unknown dim; the palette gained `magenta`/`orange`). Request rows show only `name@variant` (no method text) with an `[n]` prefix when queued; flow rows show `name  (N steps)` with no description.
- The TUI keeps one tree row per request; `activeVariant` (Map name -> variant) holds the pick, shown on the row as `name@variant` (a `+N` badge marks requests with variants when the default is active, both on the row and in the editor title). A one-line variant strip (`variantStrip`, fixed-height sibling between `editorBox` and the divider, so the editor's `width/height: 100%` stays untouched) lists all variants as clickable tabs when the selected request has any. `v`/`]` cycle next, `[` previous (list and editor panes); switching live-applies via `setVariant` (editor reload + strip + row badge) and is guarded by `!insert` and `!editorDirty()` so unsaved edits are never clobbered. The editor shows only the selected entry (marker comment included); `ctrl-s`/`:w` re-parses the on-disk file and splices the editor text back over that entry's span, refusing if the entry vanished.
- Environments are `.env.<name>` dotfiles in the collection root (dotenv syntax). The filename suffix is the environment name. There are no profiles or `termurl.toml` anymore.
- Secrets live in the environment files themselves as keys prefixed with `secret_` (masked in the TUI and in `termurl env show` until revealed). `environmentNames()` only matches `.env.<suffix>` and skips `*.example`.
- Variable precedence: captures > `--var` values > `.env.<name>` file. All variable files use plain `KEY=value`, parsed by the same hand-rolled parser (`parseVariables`); no `HURL_VARIABLE_` prefix anywhere (hurl still reads those natively from the process env, but termurl does not use them).
- The TUI writes files in place: `ctrl-s` or `:w` saves the selected entry of a `.hurl` file (spliced back into the file) and the selected `.env.<name>` file directly.
- Dirty tracking: `editorSavedText`/`envSavedText` snapshot the buffer at load/save; dirty is derived by comparing against `plainText` (so `u`ndo back to the original clears it). Dirty buffers show a `[+]` title marker plus a yellow `[<name> +a -d]` status bar badge (`dirtyBufferInfos()`, line diff stats via `diffStats`, refreshed from `setStatus`, which also runs on every `onContentChange` so the badge updates live while typing). A blocked quit (`q` / `:q`) jumps focus to the dirty buffer's window and pane via `focusDirtyBuffer` (no editor reload, so edits survive the jump). In the env list pane `i` opens the editor directly in INSERT mode, matching the requests list. Actions that would clobber a dirty buffer (moving to another request, switching variants or environments, creating/renaming/deleting, plain `q` quit, the fs watcher reload) are blocked with a warning instead; `loadEditorEntry`/`loadEnvironmentFile` skip reloading when the dirty buffer still matches their target. `:` opens a command line (`commandBuffer`, intercepted at the top of the keypress handler) only in editable file panes (request editor, env editor); it renders as a one-line bar overlaid on the bottom padding row of that pane's box (`createCommandLine`: `position: "absolute", left: 0, bottom: 0`, width floored from `box.width`, content padded to full width because `TextRenderable` only paints bg under real glyphs). `runCommandLine` accepts any combination of `w`/`q`/`x` plus `a` and a trailing `!` (`parseCommandLine`): `w` saves, `q` quits (pane close in an editor, app quit otherwise), `x` = `wq`, `a` applies to all buffers (`:wa` saves both dirty buffers, `:qa` quits the app, `:wqa`/`:xa` save all and quit), `!` forces past the dirty guard. `envDirty()` only applies when the env buffer is unmasked (`envMasked`); `envLoadedName` tracks which `.env.<name>` the buffer holds.
- Nvim-style gutters: `editor` and `envDetail` sit in a row wrap (`editorWrap`/`envDetailWrap`, `flexGrow: 1, flexBasis: 0`) next to a gutter `TextRenderable` (`editorGutter`/`envDetailGutter`) showing right-aligned line numbers, blanks for wrapped continuation rows, and `~` fillers below the last line. `renderGutter` is wrap-aware via `editorView.getLogicalLineInfo().lineSources` and renders `min(viewport.height, gutter.height)` rows so stale content never overflows the assigned height (which would cover the command line bar). Gutters refresh from `setStatus` plus `renderer.on("frame")` (fires only on real renders) and `renderer.on("resize")`. Yoga layout values are fractional (the `height` getter returns the raw float) and `editorBox.height = "55%"` therefore rounds badly, overlapping the bottom-anchored command line bar with the gutter's last row; the first frame snaps `editorBox.height` to `Math.round(...)` of its computed value (`snapEditorHeight`), and the resize handler restores the percentage so splits still adapt, then re-snaps. All pane boxes use `padding: 1` so content keeps a margin from borders and dividers.
- Mouse: all text areas are `selectable: true` (click positions the cursor, drag selects; the renderer handles both natively). `TextRenderable` defaults to `selectable: true` in @opentui/core, so list rows, the tab bar, and the status bar must set `selectable: false`, otherwise a plain click starts a drag selection and paints stray highlights. Pane boxes have `onMouseDown` handlers that sync the app's `pane`/`historyPane`/`envPane` state via `setPane`/`setHistoryPane`/`setEnvPane`, guarded by `!== target` so clicks inside an INSERT-mode editor don't exit INSERT. List rows have per-row `onMouseDown` (select; folders toggle; double-click on a request row = `tab` queue toggle, 400ms window via `lastRowClick`). Pane dividers resize by mousedown, not by `onMouseDrag` on the 1-cell bar: @opentui only captures a drag to the renderable under the pointer when the first `drag` event arrives, so a perpendicular drag off the 1-cell divider captures a neighbouring pane and the divider's handler never fires. `setupDivider` therefore records `activeDivider` (`{ divider, container, axis, resize }`) on the divider's `onMouseDown`, and `root.onMouseDrag` re-asserts the shape on every drag event (terminals may reset or defer the pointer while a mouse button is grabbed) and `onMouseUp`/`onMouseDragEnd` call `endDividerDrag()`, making the drag independent of where the pointer moves. `showDivider`/`hideDivider` also emit OSC 22 pointer shapes through `setPointerShape` (`ew-resize`/`ns-resize` per axis, `default` on out; ignored by terminals without pointer-shape support) so hovering the bar advertises the drag. Raw OSC 22 is used instead of `renderer.setMousePointer` because the library's `MousePointerStyle` has no resize shapes and its `"default"` emits an empty shape; the generic `"move"` shape is absent from common cursor themes (e.g. Adwaita) and falls back to an arrow. `endDividerDrag()` runs on window switches and `renderer.on("blur")` so a missed mouse-up can't strand the highlight or cursor.
- Response rendering: JSON bodies are pretty-printed; display is capped at `BODY_DISPLAY_LINES` (2000) lines with a truncation note, and `s` in the response pane writes the full body to `<collection>/.termurl/bodies/`. Failed assert messages are normalized by `normalizeAssertMessage` (title + caret annotation only; hurl's temp-file path and source excerpt are dropped). The response `TextareaRenderable` must keep explicit `width/height: "100%"`; without it a large body inflates its intrinsic height and breaks the flex layout.
- Cursor-follow scrolling: vim key movements go through `editBuffer` methods, which never scroll the viewport, and `editorView.getVisualCursor()` freezes once the cursor leaves the visible area of an unfocused textarea. `ensureCursorVisible` therefore maps the editBuffer's logical cursor row to a visual row via `editorView.getLogicalLineInfo().lineSources.indexOf(row)` (wrap-aware) and drives `setViewport` directly. Do not use `TextareaRenderable.moveCursor*` here: they clear the renderer selection via `updateSelectionForMovement`, and a focused textarea also treats bare keys as text input.
- History is appended to `<collection>/.termurl/history.jsonl` (gitignored; the collection walker skips `.termurl`). History records use the `environment` field; `profile` is kept only for reading pre-rename records. Runs of a variant add a `variant` field. Flow runs add `flow_id`/`step`/`flow_size` plus `flow` (saved flow name, set by `runNamedFlow`) or `queued: true` (the ad-hoc `tab` queue). The history list renders `<time>  REQUEST  <name[@variant]>  <status>`, `FLOW  <name>  (N steps)`, and `QUEUE  (N steps)`, and `historyDetailText` uses the same kind + name; records predating the `flow`/`queued` fields fall back to `FLOW` with no name. Like the other lists, history rows render in `C.fg` with selection shown only by the `C.selected` background (the status token is green/red; the active environment is `C.green`). After appending, `recordHistory` updates the in-memory `historyGroups` incrementally via `appendHistoryRecord` (new groups unshift to the front, matching the desc-by-ts order); `loadHistory` only re-parses the whole file at startup and when entering the history window.
- Hot-path caches: `readHurlFile` memoizes each `.hurl` file's text + `parseEntries` result revalidated by `statSync` mtime (so editor saves and external writes always serve fresh content), and `environmentVariables` memoizes parsed `.env.<name>` files. Both caches are cleared by the collection watcher; `environmentVariables` is also cleared by `saveEnvironmentFile`. `refreshEditorHighlights` computes `availableCaptures` and the line-start table once per call and passes the capture set into `variableSource`; do not reintroduce per-match file reads there.
